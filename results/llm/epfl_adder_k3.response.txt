# claude 2.1.282 (Claude Code)
All 27 violating paths share one carry chain: the long `o311ai_0`/`a311oi_1` spine. So WNS only moves if I fuse cells on that spine. The tail-end xnor/xor clusters (K5 onward) each touch at most 6 paths and never the worst one, so I dropped them.

On the spine, every candidate enters through a main input (x2 or x3), not through the absorbed nor2/inv/and2 cell. That means the path still goes through only one cell, and the saving comes from the fused cell being faster than the one it replaces. The `o311ai_0` cells are the undersized, slow ones, and the fused cell is built at _1 size:
- **K1** covers two `o311ai_0` instances averaging about 0.39 ns, both on all 27 paths.
- **K2** is a single `o311ai_0` at 0.45 ns, also on all 27 paths. Its worst transistor stack is 4 deep, which is still at the build limit.
- **K4** is also an `o311ai_0`, but that instance is only 0.128 ns, so there is little to gain.

**K0** already uses a _1 cell, but it has 11 instances, about 10 on each worst path (272 violating traversals). Placing the entry input nearest the output should give a small speed-up per instance, and that adds up to the largest total effect on both WNS and TNS. Its only complemented inputs (x3, x4) are off the timing path, so the extra inverters don't cost delay. **K3** is the same idea as K0 with only 2 instances, so K0 wins. None of K0, K1 and K2 share cells, so all three can apply on the same path.
